THE MODEL ERROR THIS EXPOSED, WHICH MATTERED MORE THAN THE MOVES
--------------------------------------------------------------
  A label's text direction comes from (justify ...), NOT from its angle.
  check_schematic.py derived it from the angle, so horizontal labels were
  modelled on the WRONG SIDE of their anchor. Measured at 600 dpi:

      D9         rot   0  justify left   ink 518.25..524.81  anchor 518.16  (+x)
      LEG_101_L  rot 180  justify left   ink 219.92..229.87  anchor 219.71  (+x)
      BIAS_E_L   rot 180  justify right  ink 461.52..469.78  anchor 469.90  (-x)

  rot 0 and rot 180 draw IDENTICALLY; justify decides. A first pass at
  this task rotated four labels using the angle-derived model, and the
  plot showed GAINLEG_L printed straight through C24's '10u'. That whole
  pass was reverted and redone once the direction was measured.

  Also fixed: the text-overlap check used CENTRED boxes for labels while
  the crossing check used anchored ones -- the same label had two
  different boxes in one tool depending on which loop was asking.

--------------------------------------------------------------
  The one remaining crossing, AUDIO_OUT_R against A1 on seed.kicad_sch, is
  fixed. Three coordinated edits, because it was never only about the label:

      1  GND flag at (68.58, 123.19)   rot 180 -> 0
      2  its Value text                y 126.19 -> 127.46
      3  AUDIO_OUT_R label + its wire  x 71.12 -> 67.31

  THE LABEL. 11 characters anchored at 71.12, ink ending 83.99, against an A1
  body starting at 81.28: 2.71 mm inside the socket. Its sibling AUDIO_OUT_L is
  the same 11 characters anchored at 67.31. Matching it clears A1 by 1.10 mm,
  which makes the drawing consistent with itself rather than with a preference.

  THE OBSTRUCTION, AND A DIAGNOSIS I GOT WRONG FIRST. The corridor at y 120.65
  was occupied by a power:GND flag placed at ROT 180, so its graphic draws ABOVE
  its own wire at y 120.65..123.19.

  I first called that block a modelling artefact: lib_extents() builds a box
  symmetric about the origin, and power:GND has all its ink on one side of the
  pin, so the box invents 2.54 mm of empty space. That WAS a real defect and is
  now fixed (lib_box / placed_body, asymmetric, rotation-aware, verified against
  the plot at angle 0 AND angle 180). But fixing it did not dissolve this
  obstruction: with rotation handled correctly the ink really is at
  120.65..123.19. The symmetric box gave the right answer here for the wrong
  reason. Measured on the plot the triangle spans 120.44..122.13.

  So the flag turned to rot 0 and hangs below its wire at 123.19..125.73. Of the
  five power:GND symbols on this sheet the other four are at rot 0 or 270; this
  was the only one drawn pointing up.

  A THIRD FILTER LEAK. The crossing check was skipping every symbol whose
  reference starts with '#' -- the same filter already removed from the border
  test. A label landing on a ground flag was invisible to the check whose job it
  was; the D12 / GND-arrow overlap on panel-io had to be found by a separate
  tool. Removed. With power symbols now included AND accurate boxes, the report
  is byte-identical to the conservative model: 0 findings either way.
